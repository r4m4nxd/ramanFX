## SPEC ambiguities / errors found while implementing (with bar evidence)

- **1.3 formulation.** Read literally (A = the last fixed pivot, a leg A -> X, its correction X -> Y, Y "done" by a move of
  rc x |X - Y|), a long trend never gets intermediate pivots (AUDUSD D1 from the 2025-04 low: every pullback is < 45% of
  the whole move), and the table's attributions (Sep 21 P "leg Sep 9 -> Sep 16") need the leg to restart at the reversal.
  2.16 implements the zig-zag reading: the last pivot is the pending extreme of the current leg; it is fixed when the
  counter-move is a real correction of the leg into it (leg >= minLeg, R1 or R2), then the counter-move's extreme is the
  new pending pivot; a leg < minLeg whose counter-move runs beyond the previous pivot was no leg (that pivot extends).
- **R2 "the last base"** needs a size test or tiny bases right before the extreme make 16-20% dips pivots (AUDUSD D1 Aug 11
  via the Aug 6 candle: A-D1-N; Aug 26 via Aug 24). 2.16: the base counts only if its distal -> X run is >= minLeg ATR
  (Aug 6: 1.15 ATR, Aug 24: 1.18 rejected; Oct 19 00:00 H4 2.2, Dec 13 W1 1.7, May 2025 MN 2.8 accepted).
- **OHLC order.** Outside candles decide pivots (AUDUSD H4 Oct 28 00:00 low 0.70226 then high 0.70542; gold H4 Oct 23 16:00
  high 4033.6 then low 3975.45). 2.16 reads a bullish candle low-then-high, bearish high-then-low, and a correction must
  show on a later candle than its extreme (kills single-candle P / V pairs such as AUDUSD D1 Aug 3).
- **G-D1-P "V Sep 28 4110.61"**: the Oct 7 low 4066.16 is lower and the Oct 2 bounce is 40% with no origin touch: the D1
  valley is Oct 7 (the owner's marks agree: V 10-07).
- **G-D1-X1 "no line from Aug 25"**: with the hull touch inside the confirmation window (Kevin: price TRADES below the
  Sep 2 valley, Sep 14) the line Aug 25 -> Sep 10 is clean (Aug 28 high 0.3 under it); the owner draws exactly it.
  Confirmation by a close (Sep 16) moves the hull to Sep 16 (Sep 16's own high) and loses the owner's line: 2.16 uses the
  trade-through (Kevin L5 "break below the valley low").
- **2.2 step 1 "E = the highest high before C1"** must be local (the pivot before C1), or a 2021 extreme blocks every
  later structure (AUDUSD MN 2023-10 -> 2024-08 is only found with the local reading).
- **2.2 step 4 / 1.5** ask Kevin's confirmation for every anchor 2; the owner's chain lines (AUDUSD D1 Sep 21 -> Oct 14)
  would never exist with it (the Oct 1 valley is never closed below). 2.16: chain lines are born at C' confirmation.
- **2.5 S** "a TF between B and the chart TF is SIDEWAYS" would make an H1 range override a W1 / MN reading and give a
  different DIRECTION per chart (against I2). 2.16 reads the whole chain on every chart and ignores a sideways lowest TF.
- **A-H4-P Oct 21 12:00 P 0.70354**: the highest high of that swing is Oct 22 00:00 (0.70360), 3 bars later: no extreme
  rule can mark Oct 21 12:00.
- **G-MN-L (SPEC) vs the owner**: the owner's MN line 2022-10 -> 2023-10 is cut 0.14 ATR by the Nov 2022 low; SPEC 2.2's
  clean test (p1Shift 1) skips the extreme and gives the SPEC's 2023-10 -> 2024-02.

## MQL pitfall review (by hand, no MetaEditor here)

Checked on the diff: series direction (every array is RxSer shift order, the loader fills shift i from `iOpen(i)` etc.,
the model never mixes chart-shift and TF-shift: HTF lines are mapped by `iBarShift(time)` + the fraction of the bar);
`CopyRates` not used; integer division (every slope / ratio has a double numerator; `(double)` casts in the time
fractions); no struct returned by value (`ZmMk` fills by reference) and no class passed as a pointer where a reference is
expected; locals initialised before use (`ZmPivot ext, sl` explicitly, `pk / vl` arrays set element by element); string
formatting = `DoubleToString(v, digits)` (the Python port rounds the exact binary value half-up like JS `toFixed`; MQL
`DoubleToString` may differ on an exact .5 tie only); object names: every model object uses the `RFXV2_Q` prefix, deleted
as a group before each draw, TF and line index in HTF names; an empty `OppBetween` returns +-DBL_MAX (TS NaN: never
broken; this was a real TS/MQL difference the replay caught); redraw cost: the model runs on a new chart / HTF bar or a
retry while a TF loads (<= 30), all history up to 5000 closed bars per TF, everything O(bars x small constant) except the
trend-state pivot insertion (O(pivots^2), a few hundred pivots).
